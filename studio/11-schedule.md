# 11. Запуск за розкладом

> ✅ **Уточнено під ТЗ, 2026-09-17 (D58).** Розклад — це **тригер**, а тригери за
> ТЗ §4.1.4 входять у версію робота. Тож розклад задається в редакторі робота й
> потрапляє в PROD разом із версією. Змінити розклад PROD-робота — нова версія й
> погодження за політикою. Решта документа чинна.

## Що це у нас означає

У продукті це подається як **unattended** — «робот працює вночі сам».

Технічно це **не** повний unattended. Це звичайна машина юзера, залишена
ввімкненою, з живою сесією, на якій робот запускається за розкладом.

| | Нічний запуск (наш MVP) | Повний unattended (D3b) |
|---|------------------------|-------------------------|
| Де працює | компʼютер юзера | окрема VM |
| Хто залогінений | юзер, сесія просто не закрита | ніхто; система заходить сама |
| Що потрібно налаштувати | не спати, не блокувати екран, автозапуск | автологін, служба, утримання сесії |
| Складність | мала | велика |

**Різницю варто тримати в голові.** Назва «unattended» у галузі означає саме
другий варіант, і в `LicenseType` у нас уже є `UNATTENDED_RPA`. Якщо клієнт
купує «unattended», очікуючи роботу без ввімкненого компʼютера співробітника, —
це стане розчаруванням. У документації розрізняємо, у продажах формулюємо чесно.

## Чекліст машини для нічної роботи

Без цього робот уночі не спрацює:

| Що | Навіщо |
|----|--------|
| Компʼютер не йде в сплячий режим | інакше просто спить |
| Екран **не блокується** | на заблокованому екрані елементи можуть не малюватись — робот сліпне |
| Юзер лишається залогіненим | немає сесії — немає робочого стола |
| Десктоп у автозапуску | після нічного перезавантаження агент має піднятись сам |
| Вікно оновлень Windows поза часом роботи робота | перезавантаження посеред запуску втрачає сесію |

Додатково: агент може сам тримати систему притомною під час виконання —
`pywin32` у десктопі вже є.

## Чесне попередження про безпеку

Розблокована сесія всю ніч = доступ до всіх відкритих систем під цим акаунтом
для будь-кого, хто зайде в кабінет.

Для невеликої компанії — дрібниця. Для клієнта з безпековою політикою —
стоп-фактор. Формулювання для клієнта: **ця машина має стояти там, де вночі
нікого немає.**

## Як це працює

```
  Розклад: «щодня о 03:00, робот «Накладні», машина «ПК-бухгалтерії»»
       │
       ▼  APScheduler в оркестраторі
  Створюється Job зі source = SCHEDULE
       │
       ▼
  Агент на машині отримує JOB_ASSIGN і виконує
       │
       ▼
  Вранці юзер бачить результат і логи
```

## Обмеження, про які треба памʼятати

- **одна машина — один робот одночасно**: робот займає мишу й клавіатуру;
- вранці юзер прийшов, а робот ще працює — за компʼютером не попрацюєш;
- ніхто не побачить падіння до ранку.

## Що з цього випливає для рішень

- розклад входить у MVP — див. D28;
- D11 («машина офлайн → одразу помилка») переглянуто для запусків за розкладом;
- часовий пояс беремо з організації — поле `timezone` у `organizations` уже є.
