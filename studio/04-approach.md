# 4. Підхід і інструменти

> Цей розділ іде **перед** селекторами навмисно: формат селектора — похідний від
> того, чим саме ми дивимось на екран. Спершу інструмент, потім формат.

## Головна думка: це не один світ, а кілька

Спокуса — вибрати «бібліотеку для автоматизації» і робити все нею. На практиці
різні типи програм автоматизуються **принципово різними способами**:

| Що автоматизуємо | Чим правильно | Чому не інакше |
|------------------|---------------|----------------|
| Звичайні Windows-програми (1С, ERP, бухгалтерія) | **UI Automation (UIA)** — служба Windows | штатний спосіб, дає дерево елементів з властивостями |
| Сторінки в браузері | **протокол браузера** (CDP / Playwright) | UIA бачить вміст браузера погано й повільно; DOM дає точні й стабільні селектори |
| Excel, Word, Outlook | **COM API** застосунку | клікати по клітинках повільно й крихко, коли є пряме API: прочитати діапазон однією командою |
| Citrix, RDP, самомальовані вікна | **комп'ютерний зір** | елементів не існує взагалі, є лише пікселі |

Тому Inspector і Executor треба будувати як **набір провайдерів**, а не як одну
реалізацію:

```
        Inspector / Executor
                 │
     ┌───────────┼───────────┬──────────────┐
     ▼           ▼           ▼              ▼
  desktop-uia  web-cdp   office-com    image (потім)
```

Кожен провайдер уміє дві речі: **захопити** елемент (для Inspector) і **знайти**
його потім (для Executor).

Це і є головне рішення. Вибір конкретної бібліотеки під провайдера — вже
деталь, яку можна змінити.

## Наслідок для формату селектора

Селектор має нести, **яким провайдером** його шукати. Опис елемента в
браузері й опис кнопки в 1С — це різні структури, і зводити їх до спільного
знаменника не треба.

```json
{ "provider": "desktop-uia", "strategies": [ ... ] }
{ "provider": "web-cdp",     "strategies": [ ... ] }
```

## Бібліотека для UIA-провайдера

У десктопі зараз є `pywin32`, але бібліотеки роботи з UIA немає взагалі.
Кандидати:

| | Бібліотека | Плюси | Мінуси |
|---|-----------|-------|--------|
| A | `uiautomation` | легка, прямий доступ до дерева UIA, є пошук елемента під курсором і підсвітка — саме те, що потрібно Inspector'у | тонка обгортка: складніші сценарії доведеться дописувати самим |
| B | `pywinauto` (бекенд `uia`) | зріла, багато готового: очікування, клавіатура, миша; є бекенд `win32` для зовсім старих програм | важча, повільна на великих деревах; API орієнтоване на «написати скрипт», а не «побудувати інспектор» |
| C | `comtypes` напряму до UIAutomationCore | максимальний контроль і швидкість, кешування запитів | усе писати самим: умови пошуку, обхід дерева |
| D | `FlaUI` через `pythonnet` | дуже зріла .NET-бібліотека | тягне .NET runtime усередину десктопа |

## Практична пастка: PyInstaller

Десктоп збирається PyInstaller'ом (`Tekra_new.spec`). Усі UIA-варіанти в Python
тримаються на `comtypes`, який **генерує обгортки до COM у рантаймі** й кешує їх
на диск. Це класична причина «у розробці працює, у збірці падає».

Тобто збірку треба перевірити **одразу**, як тільки провайдер запрацює, а не
перед релізом.

## Обрано для MVP (D17 ✅, D18 ✅)

Три провайдери: `desktop-uia`, `web-cdp`, `office-com`. Провайдер `image`
відкладено.

Під UIA — бібліотека `uiautomation`, схована за власним тонким інтерфейсом
провайдера.

### Що це означає за обсягом

Це **три різні інспектори**, а не один з трьома галочками:

| Провайдер | Як виглядає «захопити елемент» |
|-----------|-------------------------------|
| `desktop-uia` | юзер наводить курсор на вікно, підсвічується елемент, клік — записали шлях у дереві UIA |
| `web-cdp` | те саме, але всередині сторінки: підсвітка через протокол браузера, записали DOM-селектор |
| `office-com` | **захоплювати нічого**: юзер обирає файл, аркуш і діапазон зі списку |

### `office-com` — окремий випадок

У нього немає селекторів у звичному сенсі. Ціль — не елемент на екрані, а
адреса: «файл → аркуш → діапазон `B2:D40`». Клікати не треба взагалі.

Отже і активності свої: «прочитати діапазон», «записати значення», «зберегти
як». Це прямо впливає на набір активностей (D6).
