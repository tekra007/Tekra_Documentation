# 24. Visibility і Permissions

> Під ТЗ §4.4, §4.5, §8. Закриває відкрите питання ТЗ **#14**. Переглядає D25.
> Рішення D56 — 🟡 пропозиція пакетом, без окремого обговорення.

## Головне

ТЗ розводить два поняття (§4.4):

- **Visibility** — що людина **бачить**;
- **Permission** — що людина **може зробити**.

Можна бачити робота, але не мати права його запускати. Тому нижче дві окремі
матриці.

Ролі — наявні `USER` / `DEVELOPER` / `ADMIN` (D23). У MVP матриця **фіксована в
коді**, налаштовуваних ролей немає. Перевіряється **на бекенді** — ховати кнопки
недостатньо (D25).

## Visibility — що бачить

Верхня частина — рівно таблиця ТЗ §4.4 з нашим уточненням, що означає «за RBAC».
Нижня — сутності, яких у ТЗ немає.

| Обʼєкт | Regular User | Developer | Admin |
|--------|--------------|-----------|-------|
| DRAFT Robot | ні | так | так |
| TEST Robot | ні | так | так |
| PROD Robot | лише роботи, до яких має доступ (`robot_access`) | так | так |
| ARCHIVED Robot | ні | так | так |
| TEST Version | ні | так | так |
| PROD Version | лише активна версія доступних роботів | так | так |
| TEST Execution | ні | так | так |
| PROD Execution | лише власні запуски | усі в організації | так |
| Approval | лише статус | лише статус (D43) | так |
| Test Period | ні | власні й запитані | так |
| Audit | ні | обмежено (D43) | так |
| **Машини** | ні | усі в організації — щоб обрати, де запускати | так |
| **Облікові дані** | ні | назва й логін, **без пароля** (D20) | назва й логін, без пароля |
| **Розклади** | ні | так | так |

### Чого в ТЗ немає і як покрито

| Дія | Яким дозволом | Чому |
|-----|---------------|------|
| rollback | `ROBOT_MOVE_TO_PROD` | це теж переведення версії в PROD (D53) |
| відновлення з архіву | `ROBOT_ARCHIVE` | повертає лише в TEST, у PROD — через погодження (D55) |
| процеси й компоненти | `ROBOT_CREATE` / `ROBOT_EDIT` | окремих дозволів у ТЗ немає; це та сама робота розробника (D57, D58) |
| машини, облікові дані, розклади — зміна | лише `ADMIN` | це налаштування організації, а не робота над роботом |
| розклади — створення | `DEVELOPER`, `ADMIN` | розклад запускає PROD-робота, тож потрібен ще й `EXECUTION_RUN` |
