# 27. Тестування частин версії

> Під ТЗ §4.1.6 («запускати окремі частини») і §4.1.13 («тестувати окремі
> частини Version»). Рішення D66 — ✅ прийнято 2026-10-05.

## Що каже ТЗ

Під час TEST розробник може тестувати не лише всю версію, а й **окремі її
частини**. Що таке «частина» і як її запускати — ТЗ не уточнює.

## Що таке «частина» в MVP

Два режими:

| | Режим | Як працює | Коли зручно |
|---|---|---|---|
| **A** | **Точки зупинки** й **«Запустити до цього кроку»** | робот іде з початку й стає на паузу (`PAUSED`) на позначеному кроці. Далі — «Продовжити», «Наступний крок» або «Зупинити». На паузі видно значення змінних | треба подивитись, що відбувається на кроці 40 зі справжніми даними |
| **B** | **«Запустити виділене»** — один крок або кілька поспіль | виконуються лише виділені кроки. Змінні, які вони читають (`{{row.amount}}`), розробник заповнює у формі перед запуском | треба перевірити один клік чи селектор у вже відкритому вікні, не проходячи весь сценарій |

Так само це влаштовано в UiPath (Breakpoints, Run to / Run from this activity,
Test Activity) і в Power Automate Desktop (breakpoints, «Run from here»).

**Не в MVP — окремий запуск компонента.** У ТЗ кожен запуск належить версії
**робота** (критерій #35); компонент без робота в цю модель не лягає. Компонент
перевіряється як виділений крок усередині робота — режимом B.

## Правила

| Правило | Чому |
|---|---|
| Частковий запуск — **звичайний Execution** конкретної версії (`184.12`) з полем `scope` — яка саме частина | ТЗ: тестують «частини **Version**», а кожен запуск посилається на `Robot ID.Version Number`. Логи, аудит, історія запусків працюють як завжди |
| Лише **TEST** і лише **вручну з редактора** | у PROD виконується вся активна версія; розклад запускає робота повністю |
| Діють **ті самі 17 перевірок** перед запуском (D48), зокрема Test Period | частковий запуск робить реальні дії на машині — наприклад, натискає «Провести» в 1С |
| Незбережені зміни — як завжди за D34: перед запуском створюється нова версія | запуск завжди за конкретною версією |
| Точки зупинки й виділення **не входять у `definition`** — нової версії не створюють | це стан редактора, а не реалізація робота |
| Пауза довша за **30 хвилин → `CANCELLED`** | пауза тримає машину (D49: один запуск на машину); забута пауза займала б її назавжди. Фіксована константа оркестратора, не політика |
| На паузі видно змінні, **крім значень облікових даних** | D20: пароль не показується ніде |
| Значення змінних на паузі приходять у Studio **лише живою подією** й у логи не пишуться | у змінних бувають персональні дані з документів; логи живуть 30–90 днів (D13) |
| На Health не впливає | Health рахується лише з PROD-запусків (D52) |

## Як виглядає `scope`

Поле `executions.scope` (JSONB). Порожнє — запуск усього робота.

```json
{
  "mode": "RUN_TO",
  "breakpoints": ["s7", "s12/s3"]
}
```

```json
{
  "mode": "SELECTION",
  "steps": ["s7", "s8", "s9"],
  "variables": { "row": { "contractor": "ТОВ Ромашка", "amount": 1250.00 } }
}
```

| `mode` | Що виконується |
|--------|----------------|
| `RUN_TO` | весь робот із паузами на `breakpoints`; «Запустити до цього кроку» — це одна точка зупинки |
| `SELECTION` | лише `steps` — кроки, що йдуть поспіль; `variables` — початкові значення змінних |

Шлях кроку всередині компонента — як у логах (D58): `s12/s3`.

`steps_total` для часткового запуску — кількість кроків у `scope`, щоб лічильник
«пройдено N із M» не брехав.

## Протокол

| Повідомлення | Напрям | Що |
|--------------|--------|----|
| `EXECUTION_ASSIGN` | → агент | + `scope` |
| `EXECUTION_PAUSED` | → сервер | на якому кроці стали + значення змінних без облікових даних |
| `EXECUTION_RESUME` | → агент | продовжити до наступної точки зупинки або кінця |
| `EXECUTION_STEP` | → агент | виконати один крок і знову стати на паузу |
| `EXECUTION_CANCEL` | → агент | зупинити |

`EXECUTION_PAUSE` / `EXECUTION_RESUME` уже були в протоколі (§4.1.18) — нове лише
`EXECUTION_STEP` і змінні в `EXECUTION_PAUSED`.

## У редакторі

- точка зупинки — клік біля кроку;
- на кроці: **«Запустити до сюди»**;
- на виділених кроках: **«Запустити виділене»** → форма змінних, які читають ці
  кроки;
- на паузі: підсвічений поточний крок, панель змінних, кнопки «Продовжити» ·
  «Наступний крок» · «Зупинити».

У списку запусків частковий запуск позначено — «до кроку s7» або «кроки
s7–s9», — щоб його не плутали з повним прогоном.
