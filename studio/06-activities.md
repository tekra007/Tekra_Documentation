# 6. Активності

> ⚠️ Чернетка. Набір майже напевно зміниться, коли зʼявиться перший реальний
> робот.

**Активність** — один крок сценарію. З них юзер складає робота у Studio.

Головна спокуса тут — зробити одразу 50 активностей «щоб усе було». Головна
помилка — теж вона: кожна активність це форма у Studio, реалізація в Executor,
опис у контракті й підтримка назавжди.

## Дві осі набору

Після D17 активності діляться на два типи:

| Тип | Залежить від провайдера | Приклад |
|-----|------------------------|---------|
| **Керування потоком** | ні | умова, цикл, змінна, пауза |
| **Дії** | так | клік у вікні, ввід у браузері, читання діапазону Excel |

## Запропонований набір MVP

### Керування потоком — спільне

| Активність | Що робить |
|-----------|-----------|
| `SetVariable` | покласти значення у змінну |
| `If` / `Else` | розгалуження |
| `ForEach` | цикл по списку (наприклад, по рядках з Excel) |
| `TryCatch` | «спробувати, а якщо впало — зробити ось це» |
| `Delay` | пауза |
| `Log` | написати повідомлення у лог запуску |

### `desktop-uia` — Windows-програми

| Активність | Що робить |
|-----------|-----------|
| `AttachWindow` | обрати вікно програми, з якою працюємо далі |
| `Click` | клік по елементу |
| `TypeText` | ввести текст у поле |
| `GetText` | прочитати текст елемента у змінну |
| `SelectItem` | обрати пункт у списку / випадайці |
| `WaitForElement` | дочекатись появи елемента |
| `PressKeys` | натиснути клавіші (Enter, Ctrl+S) |
| `Screenshot` | зняти екран у лог |

### `web-cdp` — браузер

| Активність | Що робить |
|-----------|-----------|
| `OpenBrowser` | відкрити кероване вікно (D19) |
| `Navigate` | перейти за адресою |
| `ClickElement` | клік по елементу сторінки |
| `TypeText` | ввести текст |
| `GetText` | прочитати текст |
| `SelectOption` | обрати значення у `select` |
| `WaitForElement` | дочекатись елемента |
| `ExtractTable` | зчитати таблицю зі сторінки у список |
| `CloseBrowser` | закрити |

### `office-com` — Excel у MVP

Селекторів немає: ціль — «файл → аркуш → діапазон».

| Активність | Що робить |
|-----------|-----------|
| `OpenWorkbook` | відкрити файл |
| `ReadRange` | прочитати діапазон у список |
| `WriteRange` | записати список у діапазон |
| `AppendRow` | дописати рядок у кінець |
| `SaveWorkbook` | зберегти (за потреби — як новий файл) |
| `CloseWorkbook` | закрити |

Разом ~29 активностей. Word і Outlook у MVP не входять — тільки Excel.

## Канонічний сценарій, який це має покривати

Найтиповіша задача RPA виглядає так:

```
1. OpenWorkbook       «замовлення.xlsx»
2. ReadRange          A2:D100        → rows
3. ForEach  row у rows
     4. AttachWindow  «1С:Підприємство*»
     5. Click         кнопка «Створити»
     6. TypeText      поле «Контрагент» ← row.contractor
     7. TypeText      поле «Сума»       ← row.amount
     8. Click         кнопка «Провести»
     9. TryCatch      якщо не вийшло — Log і далі
10. CloseWorkbook
```

Якщо набір не дозволяє зібрати **саме це** — він недостатній.

## Ухвалено (D6a ✅, D6b ✅)

**Рівень логіки:** змінні, `If`/`Else`, `ForEach`, `TryCatch`. Це означає, що
Executor — **інтерпретатор із контекстом виконання** (сховище змінних, стек
циклів, обробка помилок), а не програвач записаних кроків.

**Значення в полях:** константа, посилання на змінну або шаблон `{{row.amount}}`.
Повноцінних виразів немає. Якщо колись не вистачить перетворення — додаємо
**окрему активність**, а не розширюємо синтаксис полів.
