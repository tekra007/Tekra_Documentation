# 45. Фаза 11 — 1С / BAF: задачі

> Що: роботи для облікових систем на платформі 1С 8.3 / **BAF** (у нас — BAS ERP 2.5 на BAF
> 8.3.19). Додано в план 2026-11-10, стартувала 2026-11-16 після обговорення. Проєктування —
> [04-approach.md](04-approach.md), [06-activities.md](06-activities.md), приклад «Excel → 1С» —
> [07-dsl.md](07-dsl.md).

## Розвідка (2026-11-16)

Тестова база BAS ERP 2.5.18.7 (BAF 8.3.19.1529, файлова, вхід `admin` без пароля; лише для
розробки): 565 довідників, 395 видів документів, 420 звітів; 5 організацій, 50 партнерів,
141 номенклатура, 37 реалізацій.

| Шлях | Результат |
|------|-----------|
| **COM** (`V83.COMConnector`, зовнішнє з'єднання) | ✅ працює: метадані, запити, довідники, документи — без вікон |
| **Вікна (UIA, тонкий клієнт)** | ⚠️ лише «рамка»: вхід, 13 розділів, меню розділу, вкладки, кнопки заголовка — з назвами. **Вміст форм** (таблиці, кнопки «Створити…», «Ще», пошук) для UIA не існує — одна безіменна панель; фільтри — поля без назв; `AutomationId` немає ніде |
| **Веб-клієнт** | ще не перевірено — потрібна публікація бази на вебсервері (Apache / IIS), модуль є в платформі |
| **Клієнт тестування** (`/TESTCLIENT`) | можливість платформи керувати формами за іменами елементів — складна інтеграція, відкладено |

Внутрішні імена метаданих — російською (`РеализацияТоваровУслуг`, `Партнер`), підписи для людей —
українською («Реалізація товарів і послуг»).

## Рішення

| # | Питання | Рішення | Чому |
|---|---------|---------|------|
| 1 | З чого почати | **провайдер `onec` — зовнішнє COM-з'єднання** (дані без інтерфейсу); другим етапом — веб-клієнт через `web-cdp` для «клацати як людина» | розвідка: UIA не бачить форм; COM закриває головний сценарій «Excel → 1С» швидко й надійно |
| 2 | Ізоляція | COM-з'єднання живе в **окремому робочому процесі** Assistant (десктопки): збій або зависання 1С не валить десктопку; Stop / кінець запуску — процес завершується | `comcntr.dll` — in-process; 1С може зависнути на блокуванні чи модальному повідомленні сервера |
| 3 | Підключення | `onec/Connect {base, user, password}` → дескриптор; `base` — рядок з'єднання 1С (`File="…"` або `Srvr="…";Ref="…"`) або шлях до теки файлової бази; логін / пароль — з облікових даних робота (D20, маскуються). Кілька баз в одному запуску — кілька дескрипторів; `connection` в інших кроках необов'язковий — типово останнє. Закривається наприкінці запуску завжди | як Excel (43): ресурс робота живе рівно один запуск |
| 4 | Активності (`onec/…`, min Assistant **1.10.0**) | `Connect` → дескриптор; `Query {text, parameters?}` → список рядків; `FindObject {type, by?, value}` → посилання або `null`; `GetObject {ref, fields?}` → об'єкт з реквізитами й табличними частинами; `CreateObject {type, fields, tables?, post?}` → посилання; `UpdateObject {ref, fields?, tables?, post?}`; `PostDocument {ref, post?}` (провести / скасувати проведення); `SetDeletionMark {ref, mark?}`; `Disconnect` | мінімум для «знайти / прочитати / створити / провести»; довільний код 1С — не в MVP |
| 5 | Як писати типи | `type` — `Catalog.Партнеры` / `Document.ЗаказКлиента` (внутрішні імена, як у мові запитів); англійські й українські префікси (`Довідник.` / `Документ.`) теж приймаються | імена об'єктів у конфігурації не перекладаються — пишемо так, як їх знає платформа |
| 6 | Значення | посилання → `{"_type": "Catalog.Партнеры", "_id": "<uuid>", "_view": "Промбуд"}` (передається в інші кроки як є); дата → ISO; число / рядок / булеве — як є; перелічення → `{"_type": "Enum.…", "_view": "…"}`; порожнє посилання → `null`; таблиці запиту → список об'єктів за іменами колонок | змінні — JSON (D22); посилання переживає перехід між кроками |
| 7 | Реквізит-посилання рядком | у `fields` / `tables` рядок для реквізиту-посилання на **один** довідник шукається за найменуванням (точно), потім за кодом; не знайдено або кілька — помилка кроку з поясненням | «Excel → 1С»: у таблиці назви контрагентів і товарів, не UUID |
| 8 | Документи | `post: true` — записати й провести (`РежимЗаписиДокумента.Проведение`); помилки проведення (повідомлення 1С) — у лог і в текст помилки кроку | людина бачить, чому документ не провівся |
| 9 | Можливість `onec` | Assistant оголошує, коли зареєстрований `V83.COMConnector` (без запуску 1С) | як `office-com` |
| 10 | Перевірки Studio-back | `onec`-крок до `Connect` — попередження `onec_not_connected`; `type` — `Kind.Name` з відомим видом (`onec_type`); `text` запиту не порожній; `fields` / `tables` / `parameters` — об'єкти JSON | 14-validation |
| 11 | Ліцензії | кожне COM-з'єднання займає ліцензію клієнта 1С / BAF на час запуску | закривається наприкінці запуску завжди (№3) |

## Задачі

| ID | Що | Де |
|----|----|----|
| **B1** ✅ | каталог `onec` (Studio-back і Desktop однаково, `catalog_version` 6); перевірки Studio-back | Studio-back, Desktop |
| **B2** ✅ | Assistant: провайдер `onec` (робочий процес, COM, значення, пошук за назвою, проведення), можливість, 1.10.0 | Desktop |
| **B3** ✅ | живий прогін на тестовій базі: Excel → номенклатура / партнер → замовлення клієнта з товарами → провести → прочитати назад → побачити в BAF | усі |
| **B4** | (наступний етап) веб-клієнт: публікація бази, робот і Inspector через `web-cdp` | Desktop, документація |

Як зроблено (B1–B3):

- **Каталог** `catalog_version` 6: 9 активностей `onec/*` (min 1.10.0), Studio-back і Desktop
  однакові. **Studio-back** — `onec_type`, `onec_object` (для «Read object» `fields` — список
  імен), попередження `onec_not_connected`.
- **Assistant (десктопка) 1.10.0** — `OneCComProvider`: COM у окремому робочому процесі
  (`multiprocessing` spawn + `Pipe`, тайм-аути 120 / 300 с, Stop і кінець запуску — процес
  завершується), посилання `{_type, _id, _view}` з `XMLTypeOf` (завжди англійською),
  пошук реквізиту за найменуванням / кодом, повідомлення 1С у текст помилки й у лог.
- Знайдено на живій базі: `FindByNumber` без дати не шукає → номер шукається запитом;
  порожня дата приходить роком 100 → `null`; `CurrentDate` у зовнішньому з'єднанні немає →
  новий документ отримує поточну дату машини (інакше 1С: «порожня дата»); `ЗаказКлиента`
  проводиться лише з `СкидкиРассчитаны: true`.

## Живий прогін (2026-11-16)

Робот RBT-59: Excel (`order.xlsx`, заголовки = реквізити `Товары`) → `onec/Connect` (тестова база,
admin) → шапка з останнього проведеного замовлення (`Query`) → `CreateObject Document.ЗаказКлиента`
з рядками з Excel, `post: true` → `GetObject` → `Disconnect`. TEST-запуск в Assistant 1.10.0.

| Що | Результат |
|----|-----------|
| Перевірка сценарію | без помилок і попереджень, `min_assistant_version` 1.10.0 |
| Запуск | `COMPLETED` 12/12 за 22 с |
| Документ | **НА00-000017** від 2026-11-16, **проведений**, партнер «Світ продуктів» |
| Рядки | «Туфлі жіночі Geox» 3 × 2400 = 7200, «Кондиціонер LG Mega S09SWC» 1 × 18500 = 18500 — товари знайдено за назвами з Excel |
| Помилка першої спроби | без дати 1С відмовила «Значення поля "Дата" не може бути порожньою датою» — текст 1С у лозі; виправлено (поточна дата) |

Обмеження, яке видно: **`СуммаДокумента` = 0** — підсумки рахують обробники форми в клієнті,
через COM їх немає; робот задає їх сам (або наступним етапом — виклик штатного перерахунку).

Не перевірено: серверна база (`Srvr=…`), вхід із паролем, зібраний exe з робочим процесом.
