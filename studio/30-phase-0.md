# 30. Фаза 0 — задачі

> Розбивка фази 0 з [10-roadmap.md](10-roadmap.md) на задачі. Складено
> 2026-10-23 на основі поточного коду (перевірено того ж дня). Правила роботи —
> [10-roadmap.md, «Як реалізуємо»](10-roadmap.md#як-реалізуємо): спершу прочитати
> доку й код, малі кроки, справжні перевірки, чесний звіт.
>
> **Мета фази 0:** усі частини існують, говорять одна з одною і мають
> фундамент безпеки — щоб тонка нитка (фаза 1) пройшла без сюрпризів.

## Як читати задачу

Кожна задача має: **що** робимо, **де** (репозиторій), **від чого залежить**,
**схема** — чи потрібні міграції (пише агент, комітить людина, AGENTS.md), і **готово,
коли** — перевіряні критерії. Задача без виконаних критеріїв — не готова.

## Порядок

```
 одразу, паралельно:   A1 CI · A2 тести з БД · A3 compose · B1 CORS · B3 перевірка організації
                       D1 схеми повідомлень · C3 config.json · I1 версія протоколу · E0 дизайн Keycloak
        ▼
 далі:                 S1 схема (після E0) → міграції етапу 1
                       C1 Studio-back · C2 Studio-front · B2 Redis · H1 планувальник
        ▼
                       D2 → D3 → D4 брокер
                       E1 → E2 / E5 → E3 / E4 вхід
        ▼
                       F1 → F2 ізоляція · F3 шифрування · G1 аудит · H2 команди через брокер · I2
```

**Найдовший ланцюг** — ідентичність: E0 → S1 → E1 → E2 → F1 → F2. Її дизайн
(E0) варто починати першим.

## Відкриті питання, які закриває E0

1. Ролі в межах організації — Keycloak чи БД оркестратора.
2. Як входить Assistant (десктоп).
3. Що з наявного входу прибираємо й що стає з таблицями адмінів і юзерів.
