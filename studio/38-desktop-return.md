## Що було до D88 і що з цього стає

До фази 1 робот був zip-архівом із Python-програмою, десктоп її розпаковував і
запускав окремим процесом (`ProcessManager`, `RobotLayout`, локальний розклад).

| Було | Що стає | Коли |
|------|---------|------|
| Картка робота: **Start** | екран **Robots**: роботи, які я можу запустити на цій машині; **Run** з формою параметрів (D22) → той самий `POST /executions` | зараз (TEST для розробника); USER / PROD — заготовка до фази 6 |

## Рішення

| # | Питання | Рішення | Чому |
|---|---------|---------|------|
| 1 | Що бачить десктоп у Robots | новий `GET /robots/runnable` оркестратора: роботи, які **ця людина** може запустити, з версією і її параметрами. Розробник — роботи в TEST / PROD, остання версія, TEST на своїй машині (D89). USER — PROD активна версія (фаза 6), до того — порожньо з поясненням. Адмін — нічого (D56) | права ті самі, що в Studio й Face; десктоп нічого не вирішує сам |
| 2 | Як десктоп запускає | HTTP до оркестратора з токеном Assistant (`Authorization`, `X-Organization-Id`) — той самий `POST /executions { robot_id, version_number, input }`; далі запуск приходить у `execution/assign`, як будь-який інший | одна дорога для запуску з усіх місць — усі 17 перевірок, аудит, черга |
| 3 | Stop на машині | локально — `RunStop.stop("Stopped at the machine by …")`, звіт `finished` `CANCELLED`; у черзі агента — одразу. Аудит на оркестраторі — `EXECUTION_CANCELLED` з цією причиною | людина за клавіатурою повинна мати аварійну зупинку без браузера |
| 4 | Не спати під час запуску | `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED \| ES_DISPLAY_REQUIRED)` на час виконання, після — скинути | 11-schedule: «агент може сам тримати систему притомною» |
| 5 | Звук | файли `success.wav` / `errr.wav` з git до D88 | були, працювали |

## Живий прогін (R6, 2026-11-08)

Assistant із розробки, кліки по справжньому вікну через UIA, тестове вікно.

| Що | Результат |
|----|-----------|
| Меню «⋯» | Runs, Robots, Schedule, Market, Settings |
| Robots | 17 роботів розробника в TEST з останньою версією й кількістю параметрів (прокрутка) |
| Run RBT-26 → форма параметрів, «Who signs in» порожнє | форма не пускає: «Fill in: Who signs in» |
| `Mariia` → Run | на картці «Sent — follow it in Runs»; тестове вікно отримало `LOGIN Mariia 7` |
| Runs під час запуску | Running, живий таймер, Pause (вимкнена, підказка про фазу 8), Stop |
| Stop посеред `Delay 30` → підтвердження | `CANCELLED` за ~1 с, «Stopped at the machine», 5/6 кроків; на оркестраторі — `CANCELLED` з тією самою причиною й `input` |
| Кінець запуску | звук і сповіщення в дзвіночку (червона позначка) |
| Schedule, Market | заготовки з поясненням і чекліст нічної роботи |

Знайдено й виправлено під час прогону:

- картки роботів стискались без прокрутки — список тепер прокручується;
- «⋯» з будь-якого екрана, крім Runs, вела на Runs замість меню — тепер відкриває меню
  (відкрите меню — назад на Runs);
- **сповіщення десктопа були зламані з D88:** десктоп слав і чекав `type_notification`
  у нижньому регістрі (`process`), оркестратор — `PROCESS`; власне сповіщення падало,
  а вхідні не розбирались. Значення enum десктопа виправлено, тест більше не закріплює
  неправильне значення.
